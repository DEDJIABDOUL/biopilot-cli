# Use better-sqlite3 for the knowledge and user databases

BioPilot needs a local SQLite engine that installs with zero compilation on the user's machine and works inside Inshellisense's Node SEA standalone binary. `node:sqlite` was rejected: it is still Release Candidate stability (not Stable) even on Node 26, its API changed as recently as 26.11, and it requires Node 22+, which conflicts with the Node 18+ floor promised for the npm install variant. `sql.js` (WASM) was rejected: it has no durable on-disk file backing, so `user.db` (usage stats, learned tools) would need to be serialized and rewritten whole on every mutation, for a packaging-simplicity gain that doesn't offset the added ~1.5MB and the rearchitecting cost.

We chose `better-sqlite3`: since v13 it ships precompiled binaries for all six target platform/arch combinations bundled inside the npm package itself, so the npm install path needs no compilation. For the standalone SEA binary, its native addon must be extracted to disk and loaded at runtime rather than embedded in the SEA blob directly — but this is not new risk: Inshellisense's own `node-pty` dependency already requires and solves exactly this pattern (per-platform optional npm packages, extracted and `dlopen`'d at runtime), so BioPilot reuses that existing, proven mechanism instead of inventing a new one.
