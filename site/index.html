Version 1.1 · 44 built-in tools · bash, zsh, fish

Autocompletion that knows your bioinformatics tools.

While you type, BioPilot suggests the options, files and values that fit fastp, samtools, bwa or minimap2, as they are actually installed in your active environment, for the project you are working in.

Install BioPilot Read the commands
Local

Private by design

No account, no network access, no telemetry, no AI service. Everything runs on your machine.

Versioned

Follows your environment

Options come from the version of the tool you really run, and follow conda activate.

Project

Knows your files

Files of the expected format first, R1/R2 mates paired, output names derived from inputs.

Gentle

Keeps general completion

git, cd, ls and other commands still complete as usual; bioinformatics tools simply come first.

01 — GET STARTED

Requirements

You need no administrator rights, no Node.js, no compiler, and no network connection after installation. BioPilot is a standalone program installed in your home folder.

PlatformSupported
Linuxx86_64 or arm64, glibc 2.28 or later (Ubuntu 20.04+, Debian 10+, Rocky or RHEL 8+)
macOS11 (Big Sur) or later, Apple silicon or Intel
WindowsWindows 10 or 11 through WSL 2, with a Linux distribution such as Ubuntu
Shellbash, zsh or fish
Toolscurl or wget, gzip, openssl, and sha256sum or shasum (shipped with these systems)
Disk spaceabout 250 MB

BioPilot helps with the bioinformatics tools you already have (in a conda environment, for example). It does not install them.

02 — GET STARTED

Installation

One command downloads the program, checks its signature and checksum, and installs it as ~/.local/bin/biopilot. Then one line in your shell's startup file starts it in every new terminal.

1. Download and install

shell
curl -fsSL https://raw.githubusercontent.com/DEDJIABDOUL/biopilot-cli/main/install.sh | sh

Without curl, use wget:

shell
wget -qO- https://raw.githubusercontent.com/DEDJIABDOUL/biopilot-cli/main/install.sh | sh

2. Start BioPilot in every new terminal

With bash, the default shell on Ubuntu:

bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
~/.local/bin/biopilot init bash | tail -n 1 >> ~/.bashrc

The first line makes the biopilot command available (skip it if ~/.local/bin is already on your PATH). The second adds the BioPilot start line at the end of ~/.bashrc; it must stay the last line of the file. With zsh, use ~/.zshrc and init zsh. With fish:

fish
fish_add_path ~/.local/bin
~/.local/bin/biopilot init fish | tail -n 1 >> ~/.config/fish/config.fish

3. Open a new terminal

Close the terminal, open a new one, and continue with Start and verify.

1. Download and install

Open the Terminal application and run:

shell
curl -fsSL https://raw.githubusercontent.com/DEDJIABDOUL/biopilot-cli/main/install.sh | sh

2. Start BioPilot in every new terminal

With zsh, the default shell on macOS:

zsh
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
~/.local/bin/biopilot init zsh | tail -n 1 >> ~/.zshrc

With bash, write to ~/.bashrc with init bash; for fish, see the Linux tab.

3. Open a new terminal window

Then continue with Start and verify.

BioPilot runs in the Windows Subsystem for Linux (WSL), a real Linux environment on Windows. It does not run in PowerShell or the Command Prompt.

1. Install WSL (if needed)

Open PowerShell as administrator and run:

powershell
wsl --install

This installs WSL 2 with Ubuntu. Restart Windows when asked, open "Ubuntu" from the Start menu, and choose a user name and password.

2. Install BioPilot inside Ubuntu

In the Ubuntu terminal, follow the Linux tab. Install BioPilot inside WSL, in the same Linux environment as your bioinformatics tools.

3. Reopen the Ubuntu terminal

Then continue with Start and verify.

Windows Terminal, from the Microsoft Store, gives the best display of the suggestions.

To work on BioPilot from the source code, with conda:

shell
git clone https://github.com/DEDJIABDOUL/biopilot-cli.git
cd biopilot-cli
conda create -n biopilot-dev -c conda-forge nodejs=22 zsh fish
conda activate biopilot-dev
npm ci
npm run build:db
npm run build
npm test
node build/index.js

npm test runs the unit tests and npm run test:e2e the end-to-end tests in real bash, zsh and fish sessions. biopilot init bash (or zsh, fish) then prints the line to add.

What the install script does

  • Downloads the standalone binary for your system from the latest GitHub Release (Node.js is embedded).
  • Checks that the release's checksums are signed by the BioPilot release key (with openssl) and that the binary matches its SHA-256 checksum. It refuses anything that fails.
  • Installs ~/.local/bin/biopilot and its resources, the Catalog included, in ~/.local/share/biopilot/.
  • Never uses sudo and never edits your files.

Install script variables

Set them before sh, for example … | BIOPILOT_VERSION=1.1.4 sh.

VariableEffect
BIOPILOT_VERSION=1.1.4install that version instead of the latest
BIOPILOT_INSTALL_DIR=~/bininstall the binary there instead of ~/.local/bin
BIOPILOT_DOWNLOAD_URL=…download from a mirror (a folder holding the release files)
03 — GET STARTED

Start and verify

Once installed, BioPilot starts by itself in every new terminal.

Check that it runs in the current terminal:

shell
$ biopilot -c
biopilot session [live]

The answer is biopilot session [live] when BioPilot is running, and biopilot session [not found] when it is not. To start it in a terminal where it is not running:

shell
biopilot

To read the real options of the tools in your active conda environment ahead of time, run once in that environment:

shell
biopilot sync

Otherwise BioPilot reads them in the background the first time you use each tool. If anything looks wrong, run biopilot doctor.

04 — USE

Using BioPilot

Type a command as usual. Suggestions appear under the cursor.

KeyAction
Tabaccept the highlighted suggestion
↑ ↓move in the list
Eschide the suggestions

Keys can be changed in rc.toml.

Examples

In a project folder that contains data/ctrl_R1.fastq.gz, data/ctrl_R2.fastq.gz, a results/ folder and ref/genome.fa indexed by bwa:

You typeBioPilot puts first
fastp --in1
fastp --in1 data/ctrl_R1.fastq.gz: FASTQ files only, R1 first
fastp --in1 data/ctrl_R1.fastq.gz --in2 data/ctrl_R2.fastq.gz, its mate
fastp --in1 data/ctrl_R1.fastq.gz --out1 results/ctrl_R1.trimmed.fastq.gz
bwa mem ref/genome.fa: the index, once
samtools sort -sort's own options
samsamtools

Tools outside the built-in list

Import any installed tool once, and BioPilot completes it from then on:

shell
biopilot learn kraken2

See biopilot learn.

Find an option by what it does

shell
biopilot search "adapter"

See biopilot search.

05 — USE

How suggestions work

Four sources decide what is suggested and in which order.

1 · Catalog

The built-in database

44 tools described: options, subcommands, value types, file formats, read pairs, derived outputs and a rank for each option. biopilot info fastp shows it.

2 · Profile

The binary you would run

Found in your shell's PATH (follows conda activate). Its version comes from conda-meta/ or the tool; its --help is read once per version. fastp 0.20.1 gets no --dedup.

3 · Project

Your files, by name

From the first parent folder holding .git, Snakefile, nextflow.config, environment.yml or .biopilot.toml: formats, read pairs, platform and assay.

4 · Habits

What you accept

Options you accept often rise a little (+15 at most). biopilot reset-usage forgets them.

The first time a tool is used, the Catalog's options (filtered by version when it is known) show while the Profile is computed in the background; biopilot sync computes them ahead of time.

Learned tools (imported with biopilot learn) are completed from their own help only: their options rank by your usage, and values are completed as files.

06 — USE

The status line

Under the suggestions of a Catalog tool, a dim line tells what BioPilot detected.

examples
 fastp 0.23.4 · conda-meta · env rnaseq
 fastp (version unknown) · reading its real options…
 fastp · not installed: options from the Catalog

While you type, it starts with the first warning of biopilot check for the line, if any. The word being typed is not checked until you move past it:

live warning
⚠ -I data/s2_R2.fastq.gz is not the mate of -i data/s1_R1.fastq.gz: samples s1 and s2 · fastp 0.23.4 · conda-meta

The warning never blocks Enter. Turn warnings off with warnings = false in rc.toml (everywhere) or .biopilot.toml (one project). Turn the whole status line off with statusLine = false in rc.toml.

07 — USE

Stop BioPilot

  • Hide the suggestions for a moment: press Esc.
  • Leave BioPilot in the current terminal: type exit. BioPilot replaces your shell in the terminal it starts in, so this also closes the terminal window or tab.
  • Stop starting BioPilot in new terminals: open your shell's startup file (~/.bashrc, ~/.zshrc or ~/.config/fish/config.fish), delete the last line, the one that contains biopilot/init, or put a # in front of it. Open a new terminal. To use BioPilot again, remove the #.
  • Remove BioPilot completely: see Uninstall.

Commands

Every biopilot command, with what it does and an example.

BioPilot's own flags go before the tool name: in biopilot info fastp --json, --json is read as fastp's option, not BioPilot's. Write biopilot info --json fastp.

CommandSummary
biopilotstart a session in the current terminal
initprepare the shell plugin, print the start line
reinitreinstall the resources after an update
doctorcheck the installation
statusenvironment, project, tools and versions detected
syncread the real options of the active environment's tools
checkwarnings about a command before it runs
infowhat the Catalog knows about a tool or an option
learnimport a tool that is not in the Catalog
searchfind options by name or description
reset-usageerase the usage statistics

-c, -V, -s, -lsession flags
biopilot

Starts a BioPilot session in the current terminal. The start line in your shell's startup file does it for you in every new terminal; run it by hand only where BioPilot is not running.

shell
biopilot
biopilot init <bash|zsh|fish>

Prepares the shell plugin and prints the source line to add to your startup file. Its last line is the start line.

shell
biopilot init zsh | tail -n 1 >> ~/.zshrc
biopilot reinit

Reinstalls the resources (Catalog, shell plugins) after an update. Run it when a terminal reports biopilot resources out of date. Your data is kept.

shell
biopilot reinit
biopilot doctor

Checks that the installation is complete: shell start lines, the tool database (Catalog), the user data (User store), the PATH and the active environment. It names each problem it finds and what to do about it.

shell
biopilot doctor
biopilot status [--json]

Shows the active conda environment, the detected project and, for each Catalog tool, the program found, its version and whether its real options (Profile) are known. --json prints it for scripts.

shell
biopilot status
biopilot status --json
biopilot sync

Computes the Profiles of the Catalog tools of the active environment: reads each tool's own --help once per version. A tool whose help cannot be read is reported failed, and the Catalog's options stay.

shell
conda activate rnaseq
biopilot sync
biopilot check [--json] "<command line>"

Warns about mistakes in a command before it runs: mismatched read pairs, missing files, an incomplete index, too many threads… It never runs the command. Full reference in Checking a command.

shell
biopilot check "fastp -i data/s1_R1.fastq.gz -I data/s1_R2.fastq.gz -o out/s1.fq.gz"
biopilot info [--json] [tool] [command…] [option]

What the Catalog knows about a tool, a subcommand or an option: its description, value type, file formats, version range.

shell
biopilot info fastp
biopilot info samtools sort -o
biopilot info --json bwa mem
biopilot learn <tool> | --list | --forget <tool>

Imports an installed tool that is not in the Catalog, from its own help. BioPilot reads its root help (--help, -h, or no argument), discovers its subcommands (one level, 50 at most) and how to print its version (--version, -V or version), and computes its Profiles. It is then completed like a Catalog tool, in the current session too.

shell
biopilot learn kraken2       # import
biopilot learn --list        # show imported tools
biopilot learn --forget kraken2

BioPilot runs an unknown tool only when you ask it to with this command; typing a command never runs it.

biopilot search [--json] [--tool <tool>] "<text>"

Lists the options of the Catalog and of learned tools whose name or description contains every word. --tool searches one tool; --json gives a machine-readable answer.

shell
biopilot search "adapter"
biopilot search --tool samtools "mapping quality"
biopilot reset-usage

Erases the usage statistics: how often you accepted each option. Profiles and learned tools are kept.

shell
biopilot reset-usage
biopilot uninstall [--yes]

Lists everything it will remove and asks for confirmation: the program, its settings, its data folder (Profiles and usage included) and the start line in your shell's startup files. Your other lines and files are not touched. --yes skips the question.

shell
biopilot uninstall
biopilot -c | -V | -s <shell> | -l
FlagEffect
-c, --checktell whether this terminal runs in a BioPilot session
-V, --verbosestart a session with verbose logging, written to ~/.local/share/biopilot/log/biopilot.log
-s, --shell <shell>start the session with this shell (bash, zsh, fish)
-l, --loginstart the shell as a login shell
09 — REFERENCE

Checking a command

biopilot check reads a command line with the Catalog and warns about mistakes that would otherwise show up hours later. It never runs the command and never reads the content of a file: only file names, whether files exist, and the CPUs available.

shell
$ biopilot check "fastp -i data/s1_R1.fastq.gz -I data/s2_R2.fastq.gz -o out/s1.fq.gz -w 64"
⚠ -I data/s2_R2.fastq.gz is not the mate of -i data/s1_R1.fastq.gz: samples s1 and s2  [read-pair]
⚠ -o out/s1.fq.gz: the folder out does not exist  [output-folder-missing]
⚠ -w 64 asks for 64 threads; only 8 CPUs are available on this machine  [threads-above-cpus]

Rules

RuleWarns when
read-pairthe two mates of a read pair belong to different samples or folders, are swapped (read 2 given as read 1), or are both read 1 (or both read 2) files
output-is-inputan output would overwrite one of the command's inputs
output-folder-missingan output file or folder is in a folder that does not exist
input-missingan input file or folder does not exist
reference-indexa Reference index named by a prefix lacks some of its files, or has none; an index folder lacks its marker file (salmon quant -i)
threads-above-cpusa thread count is above the CPUs available: a SLURM job's SLURM_CPUS_PER_TASK, else the cgroup's CPU quota, else the machine's CPUs
option-versionan option is absent from the installed version's Profile; without a Profile, outside the Catalog's version range. Nothing is said while the Profile is unknown: run biopilot sync
option-deprecatedan option the Catalog marks deprecated; an info, which does not change the exit code

What is and is not checked

  • Pipelines and lists are checked command by command (bwa mem … | samtools sort …); redirections are ignored.
  • Standard streams (-, /dev/stdin), URIs (gendb://), patterns (*.bam) and variables ($BAM) are never reported as missing.
  • After an option the Catalog doesn't know, the command's positional arguments are not checked.
  • Inputs and outputs are checked where the Catalog declares them: the main files of every Catalog tool. Learned tools are not checked.

Exit codes and JSON

CodeMeaning
0no warning (infos do not count)
1at least one warning
2the line cannot be analysed: no Catalog tool on it, an unterminated quote, or the Catalog unavailable

--json prints the result in a versioned format ("format": 1), published as a JSON Schema in schemas/check-output.schema.json, for scripts and workflow managers:

shell
biopilot check --json "$cmd" > /dev/null || echo "check this command first: $cmd"
10 — REFERENCE

Project configuration

Detection is automatic. A .biopilot.toml at the project root corrects it when needed and always has the last word. Every key is optional; an invalid file is ignored.

.biopilot.toml
assay = "rna-seq"            # rna-seq | variant-calling | unknown
platform = ["illumina"]      # illumina, nanopore, or both
results_dir = "out"          # where derived output names go (default: results/ when it exists)
reference = "ref/GRCh38.fa"  # offered first wherever a reference fits
warnings = false             # no live warning of biopilot check in this project

Settings: rc.toml

Your personal settings live in ~/.config/biopilot/rc.toml (or $XDG_CONFIG_HOME/biopilot/rc.toml).

rc.toml
statusLine = true                          # the status line under bio tools' suggestions
warnings = true                            # the first warning of biopilot check, in the status line
maxSuggestions = 5                         # suggestions shown at once
activeSuggestionBackgroundColor = "#7D56F4"
boxBorderStyle = "square"                  # or "rounded"
useAliases = false                         # complete your shell aliases' targets
useNerdFont = false

[bindings.acceptSuggestion]
key = "tab"
[bindings.nextSuggestion]
key = "down"
[bindings.previousSuggestion]
key = "up"
[bindings.dismissSuggestions]
key = "escape"

13 — REFERENCE

Privacy

What BioPilot reads, runs and stores.

  • No network, no telemetry, ever. Everything happens on your machine.
  • Reads file and folder names of the current project (depth 3, 2 000 entries at most; hidden folders, node_modules, work/ and .snakemake/ skipped), and the content of environment.yml (64 KB at most) and .biopilot.toml only. Never the content of your data files.
  • Runs only the Catalog tools and the tools you imported with biopilot learn, found in your PATH, and only with their declared version and help commands (fastp --version, fastp --help): standard input closed, 2.5 s at most. Relative PATH entries are ignored. For other commands, the completion specs inherited from Inshellisense may run the command being typed to list its values (git checkout runs git branch).
  • Shows text from outside BioPilot (file names, tools' helps) with control characters replaced by ?, so it can never send commands to your terminal.
  • Stores in ~/.local/share/biopilot/user.db (readable by you only): the Profiles, the versions found, and how often you accepted each option.
14 — MAINTAIN

Update and uninstall

Update

Run the installation command again, then open a new terminal. Your settings and data are kept.

shell
curl -fsSL https://raw.githubusercontent.com/DEDJIABDOUL/biopilot-cli/main/install.sh | sh

If a terminal reports biopilot resources out of date, run biopilot reinit. To install a specific version:

shell
curl -fsSL https://raw.githubusercontent.com/DEDJIABDOUL/biopilot-cli/main/install.sh | BIOPILOT_VERSION=1.1.4 sh

Uninstall

shell
biopilot uninstall

BioPilot lists everything it will remove and asks for confirmation: the program, its settings, its data, and the start line in your shell's startup file. The rest of your files are not touched. biopilot uninstall --yes skips the confirmation.

SymptomTry

Wrong files offeredbiopilot status shows the detected project; fix it with .biopilot.toml

16 — MAINTAIN

Frequently asked questions

Does BioPilot install fastp, samtools or other tools?

No. It helps with the tools you already have, in a conda environment or anywhere on your PATH. Without the tool installed, it still suggests the Catalog's options, and the status line says not installed.

Does it send my data anywhere, or use an AI service?

No. BioPilot has no network access, no telemetry, no account and no LLM. It reads file names, never the content of your data files. See Privacy.

Does it work on an HPC cluster without root access?

Yes. It installs in your home folder without sudo, runs on glibc 2.28 and later (RHEL, Rocky and Alma 8, Ubuntu 20.04, Debian 10), and biopilot check compares thread counts with your SLURM job's SLURM_CPUS_PER_TASK or the cgroup's CPU quota.

Does it follow conda, mamba or micromamba environments?

Yes. BioPilot follows your shell's PATH after each activation, finds the binary you would run and its version (in conda-meta/ or by asking the tool), and suggests the options of that version.

My tool is not in the list. What can I do?

Run biopilot learn <tool> to import it from its own help; it is completed from then on. To add it to the Catalog for everyone, with file formats and ranks, open a tool request or follow Adding a tool to the Catalog.

Does BioPilot run the commands I type?

It never runs a bioinformatics tool you merely type. It runs Catalog and learned tools only with their version and help commands, and an unknown tool only when you ask with biopilot learn. For general commands such as git, the inherited completion specs may run a listing command (git branch) to offer values.

Will a warning stop my command from running?

No. Live warnings appear in the status line and never block Enter. Turn them off with warnings = false in rc.toml or .biopilot.toml.

Does it replace my usual shell completion?

No. git, cd, ls and other commands still complete as usual; bioinformatics tools simply come first.

Why does exit close my terminal?

BioPilot replaces your shell in the terminal it starts in, so leaving the session also closes the window or tab. To hide suggestions, press Esc instead.

Can I use it in PowerShell or the Windows Command Prompt?

No. On Windows, BioPilot runs inside WSL 2, in the same Linux environment as your bioinformatics tools. See the Windows (WSL) tab of Installation.

How do I make sure the downloaded program is genuine?

The install script checks that the release's SHA256SUMS is signed (ECDSA P-256) by the BioPilot release key it carries, then that the binary matches its checksum. It refuses an unsigned or tampered release.

How do I cite BioPilot?

Use CITATION.cff, or the "Cite this repository" button on GitHub.
